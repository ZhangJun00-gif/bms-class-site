# 知识库文件编写要求

> 适用范围：当前 BMC3 知识库的直接 Markdown 文件（`.md`）和带图片的 ZIP 知识包（`.zip`）。
>
> 本文以当前导入器、Worker、阅读器和向量检索实现为准。更新日期：2026-07-27。

## 1. 规则级别

本文使用以下三个级别，编写时应严格区分：

- **强制**：违反后预检失败，文件不能确认导入。
- **警告**：可以继续导入，但相关内容可能被移除。目前主要是原始 HTML。
- **建议**：不影响格式校验，但会影响阅读体验、向量召回率或回答质量。

## 2. 最短合格清单

一个可以导入的知识库文件至少必须满足以下条件：

1. 文件是严格 UTF-8 编码的 `.md`，或者符合第 4 节目录结构的 `.zip`。
2. Markdown 必须且只能有一个 H1（`#`），并且 H1 位于所有 H2 之前；H1 只作为管理端版本标识，普通用户阅读时不会显示。
3. 至少有一个 H2（`##`）；所有正文都位于某个 H2-H6 标题下。
4. 标题只能逐级下降，不能从 H2 直接跳到 H4。
5. 每个标题的可见文本非空、不超过 200 个字符，标题 Markdown 源码不超过 4 KiB；完整标题路径不能重复。
6. 每个 H2 至少包含直属正文或子标题。
7. H2 在同一知识库的活动内容中必须唯一；确认导入前必须核对预检显示的是“新建文档”还是“整份替换”。
8. 直接 `.md` 不得包含图片；有图片时必须使用 ZIP 知识包。
9. ZIP 中每张图片都被 Markdown 引用，且每个引用都有明确的替代文本。
10. LaTeX 使用本文支持的定界符，并采用 KaTeX 兼容语法。
11. 文件和内容规模不超过第 12 节的全部限制。

## 3. 选择 `.md` 还是 `.zip`

### 3.1 直接 Markdown

不需要插图时优先上传 `.md`：

```text
生物化学.md
```

**强制要求：**

- 扩展名必须是 `.md`，大小不超过 10 MiB。
- 文件必须是严格 UTF-8 编码；允许 UTF-8 BOM，导入时会移除。
- 不允许非法 UTF-8 字节或 NUL 字符。
- 不得出现 Markdown 图片节点，包括行内图片和引用式图片。

普通链接不是图片，可以使用，但仍受第 9 节的链接规则限制。

### 3.2 ZIP 知识包

只要正文需要引用本地图片，就必须使用 `.zip`。ZIP 中也必须包含 Markdown 主文件，不能只上传图片。

## 4. ZIP 目录和文件要求

### 4.1 唯一允许的结构

```text
生理学.zip
├── 生理学.md
└── image/
    ├── cardiac-cycle.png
    ├── ecg-lead-I.jpg
    └── pressure-volume.webp
```

**强制要求：**

- ZIP 根目录必须且只能有一个 `.md` 文件，文件名不限。
- 根目录 Markdown 仍须满足本文全部编码、标题、正文、公式和容量要求。
- 图片只能放在根目录下的一层 `image/` 目录中。
- `image/` 可以省略，但包内没有图片时通常应直接上传 `.md`。
- 不得在 ZIP 外再套一层同名目录。
- 不得包含说明文件、隐藏文件、系统元数据或其他未列出的文件。
- ZIP 不得加密，不得包含符号链接。

以下结构无效：

```text
# 错误：Markdown 不在 ZIP 根目录
生理学.zip
└── 生理学/
    ├── 生理学.md
    └── image/a.png

# 错误：图片目录超过一层
生理学.zip
├── 生理学.md
└── image/chapter-01/a.png

# 错误：包含额外文件
生理学.zip
├── 生理学.md
├── README.txt
└── image/a.png
```

### 4.2 ZIP 路径规则

**强制要求：**

- entry 路径最长 500 个字符。
- 路径使用正斜杠 `/`，不得使用反斜杠 `\`。
- 不得包含绝对路径、Windows 盘符、NUL、`.` 或 `..` 路径段。
- 文件名按 Unicode NFC 规范化后处理。
- 文件名按不区分大小写的键检查重复。例如 `image/a.png` 与 `image/A.PNG` 会被判为冲突。
- Markdown 中的图片路径必须与 ZIP 内文件名逐字符、逐大小写一致。

为减少跨平台问题，**建议**文件名只使用 ASCII 小写字母、数字、连字符和下划线，例如 `cardiac-cycle_01.png`。

## 5. Markdown 标题与层级

### 5.1 标题职责

| 层级 | 写法 | 在知识库中的职责 |
| --- | --- | --- |
| H1 | `# 教材或文档标题` | 管理端版本标识；全文必须且只能有一个，普通用户端不显示 |
| H2 | `## 章名` | 知识库顶层章节；在同一知识库的活动内容中必须唯一 |
| H3 | `### 节名` | 章节内的主要知识单元 |
| H4 | `#### 子节名` | H3 下的细分知识单元 |
| H5 | `##### 条目名` | 更细的知识单元 |
| H6 | `###### 条目名` | 最深层知识单元 |

H2 只对应当前知识库自己的章节，不会修改全局学科章节。上传文件中的任一 H2 命中一个既有逻辑文档时，系统会把当前文件作为该文档的候选新版本并执行整份替换，不会只更新重复的 H2。

H1 与 H2-H6 都允许受控的行内 Markdown，包括公式、粗体、斜体、删除线、行内代码以及安全链接。H1 会在管理端以同一 KaTeX 渲染链显示，但为了让版本列表清楚稳定，**建议 H1 使用简洁纯文本并包含可辨识的版本信息**。标题不得包含图片、块级公式、原始 HTML、换行或其他块级内容，也不要依赖链接跳转表达关键信息。

### 5.2 合法层级示例

```markdown
# 生理学

## 血液循环

本章概述体循环和肺循环。

### 心动周期

心动周期是心脏一次收缩和舒张构成的机械活动周期。

#### 心室收缩期

心室收缩期包括等容收缩期和射血期。

##### 等容收缩期

房室瓣关闭，半月瓣尚未开放，心室容积不变。
```

### 5.3 标题硬性规则

**强制要求：**

- H1 必须且只能出现一次。
- H1 必须位于全部 H2 之前。
- 至少有一个 H2。
- H2-H6 不得跳级。例如 H2 后可以出现 H3，不能直接出现 H4。
- 标题的规范化可见文本必须为 1-200 个字符。
- 每个标题去掉 `#` 前缀后的 Markdown 源码不得超过 4 KiB。
- 标题只允许文本、强调、删除线、行内代码、安全的 HTTP/HTTPS 或页内链接以及行内公式；不得包含图片、块级节点、原始 HTML 或换行。
- 标题比较会执行 Unicode NFC、去除首尾空白并将连续空白折叠为一个空格。
- 同一文档版本内，规范化后的完整路径不得重复。
- H1 前、H1 与首个 H2 之间、以及其他不属于 H2-H6 节点的位置不得出现实质正文。
- 每个 H2 必须有直属正文或至少一个子标题；H2 可以只作为含有子节点的章节容器。

以下写法会因跳级失败：

```markdown
# 生理学

## 血液循环

#### 心室收缩期

正文。
```

以下写法会因完整路径重复失败：

```markdown
# 生理学

## 血液循环

### 心动周期

第一段正文。

### 心动周期

第二段正文。
```

不同父路径下可以使用相同的末级标题。例如“血液循环 > 调节”和“呼吸 > 调节”是两个不同路径。

### 5.4 H2 唯一性与整份替换

H2 唯一性按规范化后的可见文本，在同一知识库各未删除逻辑文档的当前活动版本之间检查。上传和确认时遵循以下规则：

- 上传文件的全部 H2 都未命中既有逻辑文档时，预检显示“新建文档”。确认后创建新的逻辑文档，其首次创建时间决定在整库连续正文中的固定位置。
- 一个或多个 H2 命中同一个既有逻辑文档时，预检显示“整份替换”、目标文档和命中的 H2。确认后当前文件会成为该逻辑文档的完整候选新版本；旧版本中未出现在新文件里的 H2 和正文不会继续保留。
- H2 同时命中多个既有逻辑文档时，预检以 `H2_REPLACEMENT_AMBIGUOUS` 失败，必须先调整文件或现有文档，系统不会猜测替换目标。
- 在“写入目标”中显式选择既有逻辑文档时，即使 H2 名称全部改变，也会创建该文档的新版本；但新 H2 仍不得与其他逻辑文档冲突。
- 预检不是最终占用凭证。确认导入和发布时系统会再次检查 H2 唯一性；发生并发变化时会拒绝本次操作。
- 发布新版本只切换目标逻辑文档的活动版本，不改变该文档的首次创建时间和整库阅读位置。

因此，**确认任何“整份替换”任务前，必须检查候选文件是否包含目标逻辑文档应保留的全部 H2 和正文**。

### 5.5 正文归属与阅读行为

标题后的正文只归属于该标题，直到遇到下一个标题；子节点正文不会复制到父节点。

普通用户查看知识库时，系统将各逻辑文档按首次创建时间排序，选择每个文档当前已发布的活动版本，并把所有 H2-H6 标题及正文拼接成一份连续 Markdown。用户端不显示 H1、文档边界、文档选择器或版本切换控件。

阅读视图提供 Typora 式 H2-H6 大纲；思维导图以知识库名为根节点，只显示同一组 H2-H6 标题层级。点击大纲或思维导图节点会回到连续正文中的对应标题。正文采用动态 RenderBlock 窗口，加载前后内容时保持当前阅读位置不回弹，这不会改变文件中的标题和正文顺序。

因此：

- **建议**用 H3 表示连续正文中的主要主题。
- **建议**用 H4-H6 表示该主题内部确有从属关系的内容，不要只为改变字体大小而增加层级。
- **建议**让同级标题保持同一种分类维度，例如同为阶段、器官、疾病或机制，使大纲和思维导图都能准确表达结构。

## 6. 正文内容要求

### 6.1 支持的 Markdown

当前支持常用 Markdown 和 GFM 内容，包括：

- 段落、粗体、斜体、删除线；
- 有序列表和无序列表；
- 引用；
- 行内代码和围栏代码块；
- GFM 表格；
- 分隔线；
- 普通链接和引用式链接；
- 数学公式；
- ZIP 知识包中的本地图片。

引用式链接和引用式图片会在导入时解析为自包含的普通链接或图片引用。

### 6.2 原始 HTML

原始 HTML 不是知识正文的受支持格式。例如：

```html
<div class="note">重点内容</div>
<script>alert('x')</script>
```

正文中的这些 HTML 节点会产生 `RAW_HTML_IGNORED` 警告，并从阅读内容、分片和向量文本中移除；标题中的 HTML 也不受支持，可能在标题规范化时直接移除。标签中的文字不能视为可靠保留内容。

**要求：**不要使用 HTML 实现排版、颜色、脚注、折叠区、iframe、音视频或脚本；应改写为标准 Markdown。

### 6.3 超长块

系统会在段落、列表、表格、代码块等顶层 Markdown 块之间组织阅读块：

- 目标阅读块大小是 24 KiB；超过目标时系统会尽量在顶层块之间拆分。
- 单个不可拆分 Markdown 块不得超过 64 KiB，否则预检失败。

因此不要编写一个超长段落、一张极大的表格、一个极大的列表或一个超过 64 KiB 的代码块。将其拆成多个段落、多个小表，或用适当的子标题分组。

## 7. 数学公式要求

### 7.1 支持的定界符

支持以下四种形式：

```markdown
行内公式：$E = mc^2$

行内公式：\(E = mc^2\)

块级公式：

$$
P = \frac{F}{A}
$$

块级公式：

\[
P = \frac{F}{A}
\]
```

系统会将 `\(...\)` 和 `\[...\]` 规范化为对应的美元符号形式后保存到阅读块。代码跨度和代码围栏中的定界符按代码处理，不会被识别为公式。

### 7.2 标题中的公式

H2-H6 标题允许行内公式，并会在连续正文、Typora 式大纲和思维导图中使用同一 KaTeX 渲染结果。H1 中的行内公式也能在管理端版本标识和候选预览中渲染，但普通用户端不会显示 H1；为便于版本识别，仍建议 H1 使用简洁纯文本：

```markdown
### $L$-$\alpha$ 氨基酸的构型

#### 当 $x_i^2 > 0$ 时的性质
```

标题的稳定路径使用去除 Markdown 样式后的可见文本；标题原始 Markdown 另行保留用于显示。因此不要仅依赖粗体、链接等样式来区分两个标题。

### 7.3 公式编写规则

**强制要求：**

- 全文数学节点最多 10,000 个，正文和所有标题中的公式均计入；H1 即使误写公式也会占用该数量。
- 单个公式源码不超过 16 KiB。
- 全部公式源码合计不超过 1 MiB。

**建议：**

- 定界符必须成对闭合。未闭合的定界符可能被当作普通文本，预检不一定能发现，因此必须在阅读预览中检查。
- 使用 KaTeX 支持的数学命令，不要粘贴完整 LaTeX 文档、导言区、宏包声明或依赖 `\begin{document}` 的内容。
- 块级公式的起止定界符各占一行，避免与普通文字混排造成解析歧义。
- 金额中的美元符号写为 `\$`。
- 当公式紧邻数字或标点、美元定界符可能产生歧义时，优先使用 `\(...\)`。
- 公式中的中文说明优先使用 `\text{...}`，不要使用原始 HTML 调整样式。
- 复杂推导拆成数个公式，并在公式前后写明变量含义、单位和结论。

示例：

```markdown
肺泡通气量为：

$$
\dot V_A = (V_T - V_D)f
$$

其中，$V_T$ 为潮气量，$V_D$ 为生理无效腔量，$f$ 为呼吸频率。
```

## 8. 图片要求

### 8.1 路径和引用

图片必须使用标准 Markdown 图片语法，并且路径只能是 `image/<文件名>`：

```markdown
![心动周期中压力、容积和瓣膜状态的对应关系](image/cardiac-cycle.png)
```

引用式写法也可以使用：

```markdown
![心动周期示意图][cardiac-cycle]

[cardiac-cycle]: image/cardiac-cycle.png
```

**强制要求：**

- 只允许 `.jpg`、`.jpeg`、`.png`、`.webp` 扩展名。
- 文件实际内容必须能完整解码为 JPEG、PNG 或 WebP；扩展名和真实格式都应正确，只把 GIF、TIFF 等文件改成受支持扩展名仍会失败。
- 图片路径必须是 `image/` 下的一层相对路径。
- 不允许远程 URL、绝对路径、Data URI、协议相对 URL、反斜杠、查询参数或 URL 片段。
- 不允许编码后的路径穿越标记，例如 `%2e`、`%2f` 或 `%5c`。
- 路径必须精确匹配 ZIP entry 的 Unicode 和大小写。
- Markdown 引用的每张图片必须存在。
- ZIP 中的每张图片必须至少被 Markdown 引用一次；未引用图片同样会使预检失败。

同一路径可以在正文中出现多次，每次出现都会保留独立阅读位置。

### 8.2 替代文本

每个图片引用必须包含 1-300 个字符的非空替代文本：

```markdown
<!-- 合格 -->
![肾小球滤过膜三层结构：有孔内皮、基膜和足细胞裂孔膜](image/filtration-barrier.png)

<!-- 不合格：替代文本为空 -->
![](image/filtration-barrier.png)
```

替代文本会执行 Unicode NFC、去除首尾空白并折叠连续空白。同一图片路径被多次引用时，规范化后的替代文本必须完全一致。

系统不会对图片做 OCR、视觉理解或视觉向量化。进入分片、Embedding 和 AI 上下文的是替代文本，而不是图片像素。因此替代文本应写出图片表达的医学对象和关键信息，不应只写“图 1”“示意图”或文件名。

### 8.3 图片质量和处理

**强制要求：**

- 每张源图不超过 10 MiB。
- 每张源图不超过 32,000,000 像素，即 `宽度 × 高度` 不超过该值。
- 每个 ZIP 最多 1,000 张图片。
- 图片必须能被系统处理为不超过 300 KiB 的私有 WebP；处理失败会使预检失败。

导入时系统会读取方向信息、按需缩小图片并转换为 WebP，最长输出宽度不超过 1,920 像素。原始文件名不会作为公开媒体地址暴露。

**建议：**

- 上传前裁掉无关页边和大面积空白。
- 医学图中的文字、箭头和图例应在缩小后仍清晰可辨。
- 优先使用清晰的原始截图或导出图，不要反复压缩已有低质量图片。
- 不要用图片承载本可直接写成 Markdown 的定义、表格或关键结论。

## 9. 链接要求

显式 Markdown 链接的可见文字会进入检索文本，其目标 URL 不会进入 Embedding；裸写 URL 时，URL 本身属于可见文字，可能进入检索文本。阅读器只允许安全链接：

- 绝对 `https://` 和 `http://` 链接；
- `#` 开头的页内锚点。

其他协议和不安全链接不会形成可用跳转。相对文档链接、`mailto:`、`javascript:`、`data:` 等不要作为知识内容的必要组成部分。

**建议**在链接前直接写明来源名称、关键结论和必要的引用信息，不能要求读者必须访问外部页面才能理解正文。例如：

```markdown
世界卫生组织《某指南（2025）》建议……。原文见[指南页面](https://example.org/guideline)。
```

## 10. 面向检索和问答的编写建议

格式合法并不等于检索质量良好。向量化时系统会把“学科 > 知识库 > 章节 > 完整标题路径”与正文共同作为语义输入；正文按约 450 token 的目标大小分片，单片上限约 600 token，相邻片段保留约 60 token 重叠。作者不需要手工标记分片，但应按以下方式组织内容。

### 10.1 一个标题只讲一个可检索主题

- H2 对应教材章或稳定的大主题。
- H3-H5 对应定义、结构、机制、诊断、治疗、比较等单一主题。
- 标题应包含有区分度的医学名称，避免大量使用“概述”“其他”“补充”“注意事项”。
- 一个知识单元通常以数个短段落为宜；内容过长时按真正的语义边界增加子标题。

### 10.2 让答案在局部上下文中自足

- 第一次出现缩写时同时写出中文全称、英文全称和缩写。
- 代词应有明确指代，避免整段只写“其”“该病”“上述结构”。
- 定义、条件、例外、数值和单位尽量放在同一知识单元中。
- 对容易混淆的概念明确写出共同点和区别。
- 否定、禁忌和例外使用完整句表达，不依赖颜色、图标或排版暗示。
- 表格前后补充一句可检索的文字结论；不要让关键答案只存在于图片中。

### 10.3 保持来源忠实

- 不添加无法从教材或指定资料支持的医学结论。
- 保留限定词，例如“通常”“可能”“在……条件下”，不要把相关性改写为因果性。
- 数值必须带单位；范围、上下限和适用人群必须完整。
- 对版本敏感的指南、分期或剂量注明来源名称和年份。
- 多个来源存在冲突时，应分开陈述来源和口径，不自行合并成一个确定结论。

## 11. 完整示例

### 11.1 无图片的 `.md` 示例

````markdown
# 生理学知识库

## 呼吸

呼吸系统完成肺通气、肺换气、气体运输和组织换气。

### 肺通气

肺通气是肺与外界环境之间的气体交换过程。

#### 肺泡通气量

每分钟肺泡通气量的计算式为：

$$
\dot V_A = (V_T - V_D)f
$$

其中：

- $V_T$：潮气量，单位为 mL；
- $V_D$：生理无效腔量，单位为 mL；
- $f$：呼吸频率，单位为次/min。

| 因素 | 变化 | 对肺泡通气量的影响 |
| --- | --- | --- |
| 潮气量 | 增加 | 增加 |
| 无效腔量 | 增加 | 减少 |
| 呼吸频率 | 在其他条件不变时增加 | 增加 |

### 肺换气

肺换气是肺泡与肺毛细血管血液之间的气体交换过程。

#### 气体扩散

气体扩散速率与膜两侧分压差和扩散面积成正比，与膜厚度成反比。
````

### 11.2 带图片的 ZIP 示例

ZIP 结构：

```text
循环生理.zip
├── 循环生理.md
└── image/
    ├── cardiac-cycle.png
    └── pressure-volume-loop.webp
```

`循环生理.md`：

```markdown
# 循环生理

## 心脏泵血功能

心脏泵血功能由有序的电活动和机械活动共同完成。

### 心动周期

心动周期包括心房和心室的收缩期与舒张期。

![心动周期各阶段中主动脉压、心室压、心房压、心室容积和心音的对应关系](image/cardiac-cycle.png)

#### 压力-容积环

压力-容积环用于描述一个心动周期中心室压力与容积的关系。

![左心室压力-容积环及等容收缩、射血、等容舒张和充盈四个阶段](image/pressure-volume-loop.webp)
```

## 12. 容量限制总表

下表是当前实现允许的最大值。部署配置可以在这些上限以内进一步收紧，因此接近极限的文件不保证一定能获得容量配额。

| 项目 | 最大值 | 超限结果 |
| --- | ---: | --- |
| 直接 Markdown 文件 | 10 MiB | 拒绝上传或预检失败 |
| ZIP 压缩文件 | 200 MiB | 拒绝上传 |
| ZIP 全部文件声明展开大小 | 500 MiB | 预检失败 |
| 单个 ZIP entry 压缩比 | 100:1 | 预检失败 |
| ZIP entry 路径长度 | 500 字符 | 预检失败 |
| 根目录 Markdown | 恰好 1 个 | 预检失败 |
| 图片文件数 | 1,000 张 | 预检失败 |
| 单张源图 | 10 MiB | 预检失败 |
| 单张源图像素 | 32,000,000 | 预检失败 |
| 单张处理后图片 | 300 KiB | 无法压缩到该值则预检失败 |
| H2-H6 标题节点 | 10,000 个 | 预检失败 |
| 单个标题可见文本 | 200 字符 | 预检失败 |
| 单个标题 Markdown 源码 | 4 KiB | 预检失败 |
| 估算知识分片 | 25,000 个 | 预检失败 |
| 分片目标大小 | 450 token | 系统自动组织，不是拒绝线 |
| 单个分片上限 | 600 token | 系统自动拆分 |
| 分片重叠 | 60 token | 系统自动生成 |
| 阅读块目标大小 | 24 KiB | 系统尽量在顶层块之间拆分 |
| 单个不可拆分 Markdown 块 | 64 KiB | 预检失败 |
| 数学节点 | 10,000 个 | 预检失败 |
| 单个公式源码 | 16 KiB | 预检失败 |
| 全部公式源码 | 1 MiB | 预检失败 |
| 图片替代文本 | 1-300 字符 | 预检失败 |

### 12.1 私有知识库配额

单文件通过上述校验后，确认导入时仍需满足当前用户和系统的剩余容量。当前默认的单用户私有知识配额为：

| 项目 | 单用户上限 |
| --- | ---: |
| 私有知识库 | 2 个 |
| 活动私有文档 | 10 个 |
| 活动私有知识分片 | 2,000 个 |
| 私有知识图片 | 200 张 |
| 处理后私有图片总量 | 50 MiB |

共享库还受全局活动分片和向量点容量限制。预检通过只表示文件合同有效，不代表已为导入预留最终容量；以确认导入时的容量检查结果为准。

## 13. 常见错误与修正

| 错误码或现象 | 原因 | 修正方式 |
| --- | --- | --- |
| `H1_COUNT` | 没有 H1 或存在多个 H1 | 全文只保留一个 `# 标题` |
| `H1_POSITION` | H1 出现在 H2 之后 | 将唯一 H1 移到文件开头 |
| `MISSING_H2` | 没有 H2，或正文未从 H2 开始 | 至少添加一个 `## 章节` |
| `BODY_OUTSIDE_H2` | 正文位于 H2 之前或标题树之外 | 将正文移入适当的 H2-H6 下 |
| `HEADING_LEVEL_SKIP` | 标题从 H2 跳到 H4 等 | 补齐 H3，或把 H4 改为 H3 |
| `EMPTY_HEADING` | 标题没有可见文本 | 为标题填写明确名称 |
| `HEADING_TOO_LONG` | 标题超过 200 字符 | 缩短标题，将解释移到正文 |
| `HEADING_MARKDOWN_TOO_LARGE` | 标题 Markdown 源码超过 4 KiB | 精简标题中的公式、链接或样式源码 |
| `HEADING_CONTENT_UNSUPPORTED` | 标题包含图片、块级公式、HTML 等不支持内容 | 将其移到正文，标题只保留受支持的行内内容 |
| `HEADING_LINK_UNSAFE` | 标题链接不是 HTTP、HTTPS 或合法页内锚点 | 删除链接或改用安全目标 |
| `HEADING_LINE_BREAK` | 标题包含换行 | 将标题写在单独一行并移除内部换行 |
| `DUPLICATE_NODE_PATH` | 同一完整标题路径重复 | 合并内容或为同级节点使用不同标题 |
| `EMPTY_CHAPTER` | H2 既无正文也无子标题 | 添加正文/子标题或删除该 H2 |
| `NODE_LIMIT` | H2-H6 标题节点超过 10,000 个 | 将内容拆为多个逻辑文档 |
| `H2_REPLACEMENT_AMBIGUOUS` | 当前文件的 H2 同时命中多个逻辑文档 | 调整文件范围或既有文档，确保只对应一个目标 |
| `H2_REPLACEMENT_CHANGED` | 预检后知识库发生变化，整份替换目标已改变 | 重新上传并核对新的预检结果 |
| `DIRECT_MARKDOWN_IMAGE` | 直接 `.md` 包含图片 | 改用符合结构的 ZIP 知识包 |
| `IMAGE_PATH_INVALID` | 图片不是 `image/<文件名>` | 移动图片并修正 Markdown 路径 |
| `IMAGE_ALT_INVALID` | 替代文本为空或超过 300 字符 | 写 1-300 字符的有效描述 |
| `IMAGE_ALT_CONFLICT` | 同一路径使用了不同替代文本 | 统一该图片所有引用的替代文本 |
| `IMAGE_NOT_FOUND` | Markdown 引用的图片不在 ZIP 中 | 加入文件或删除引用 |
| `IMAGE_UNUSED` | ZIP 中图片未被正文引用 | 添加引用或从 ZIP 删除该图片 |
| `IMAGE_PATH_CASE_MISMATCH` | 引用路径与 ZIP 文件名大小写不同 | 逐字符统一两者 |
| `IMAGE_DECODE_FAILED` | 图片格式不受支持、图片损坏、像素超限或无法压到 300 KiB | 重新导出受支持且清晰的图片 |
| `RAW_HTML_IGNORED` | 正文包含原始 HTML | 改写为标准 Markdown；该项目前是警告 |
| `MATH_EXPRESSION_TOO_LARGE` | 单个公式超过 16 KiB | 将公式拆成多个有说明的公式 |
| `MATH_COUNT_LIMIT` | 数学节点超过 10,000 个 | 合理合并或拆分文档 |
| `MATH_TOTAL_SIZE_LIMIT` | 公式源码总量超过 1 MiB | 精简公式或拆分文档 |
| `RENDER_BLOCK_TOO_LARGE` | 单个段落、表格、列表或代码块超过 64 KiB | 在顶层边界拆分内容 |
| `CHUNK_LIMIT` | 估算分片超过 25,000 个 | 将内容拆为多个文档 |
| `ZIP_MARKDOWN_COUNT` | 根目录 `.md` 不是恰好一个 | 只保留一个根目录 Markdown |
| `ZIP_UNEXPECTED_ENTRY` | ZIP 有额外目录、嵌套图片或未知文件 | 按第 4.1 节重建 ZIP |
| `ZIP_DUPLICATE_ENTRY` | 文件名重复或仅大小写不同 | 重命名并同步修改引用 |
| `ZIP_UNSAFE_PATH` | ZIP 包含不安全路径 | 使用普通根文件和 `image/文件名` |
| `ZIP_ENCRYPTED` | ZIP 已加密 | 创建不加密 ZIP |
| `ZIP_SYMLINK` | ZIP 中包含符号链接 | 将目标内容作为普通文件重新打包 |
| `ZIP_EXPANDED_TOO_LARGE` | ZIP 声明的总解压大小超过 500 MiB | 删除无关内容或拆分知识包 |
| `ZIP_FILE_COUNT_LIMIT` | ZIP 文件总数超过允许范围 | 减少图片数量并移除额外文件 |
| `ZIP_RATIO_LIMIT` | entry 压缩比异常 | 用常规压缩方式重新打包 |

## 14. 上传前自检清单

### 14.1 文件和结构

- [ ] 文件扩展名是 `.md` 或 `.zip`。
- [ ] Markdown 使用严格 UTF-8 编码，无 NUL 字符。
- [ ] ZIP 根目录只有一个 `.md` 和可选的 `image/`。
- [ ] ZIP 没有额外目录、隐藏文件、符号链接或加密 entry。
- [ ] 文件、图片、公式和节点数量均未接近第 12 节限制。

### 14.2 标题和正文

- [ ] 全文恰好一个 H1，且 H1 位于全部 H2 之前；H1 能在管理端清楚标识当前版本。
- [ ] 至少一个 H2，所有正文均位于 H2-H6 下。
- [ ] H2-H6 没有跳级，完整标题路径没有重复，单个标题源码不超过 4 KiB。
- [ ] 每个 H2 有正文或子标题。
- [ ] H2 名称已与目标知识库核对，预检中的“新建文档”或“整份替换”符合预期。
- [ ] H3-H6 的从属关系适合在连续正文、Typora 式大纲和思维导图中展示。
- [ ] 没有用原始 HTML 承载必要内容。
- [ ] 没有单个超长段落、列表、表格或代码块。

### 14.3 公式

- [ ] 定界符成对闭合，块级公式的定界符单独占行。
- [ ] 公式使用 KaTeX 兼容命令，无完整 LaTeX 文档结构。
- [ ] 标题公式和正文公式都在实际预览中检查过。
- [ ] 金额符号已转义，容易歧义的行内公式改用 `\(...\)`。

### 14.4 图片

- [ ] 只有 ZIP 知识包使用图片。
- [ ] 所有图片都位于 `image/` 一层目录并使用受支持格式。
- [ ] 每个 Markdown 引用都精确命中 ZIP 内文件名和大小写。
- [ ] 每张 ZIP 图片都至少被引用一次。
- [ ] 每个替代文本为 1-300 字符，同一路径的文本完全一致。
- [ ] 替代文本可以独立说明图片的医学对象和关键信息。
- [ ] 图片在缩小和 WebP 转换后仍能清楚辨认文字、箭头和图例。

### 14.5 检索质量

- [ ] 每个知识节点聚焦一个明确主题。
- [ ] 标题包含具体医学术语，而不是泛化标签。
- [ ] 缩写首次出现时给出中英文全称。
- [ ] 定义、条件、例外、数值和单位在局部上下文中完整。
- [ ] 重要结论不只存在于图片、链接或排版样式中。
- [ ] 对容易混淆的概念写明区别，对否定和例外使用完整句。

## 15. 导入流程要求

1. 在目标知识库的上传区选择 `.md` 或 `.zip`。若要明确更新某个既有逻辑文档，可在“写入目标”中选择它；否则保留“新建文档”，由 H2 冲突规则自动判定是否整份替换。
2. 上传后等待异步预检完成。预检只分析当前候选文件，不会把同一知识库中的其他文档拼接进候选预览。
3. 查看错误、警告、节点数、估算分片数、图片数、处理后图片大小，以及“新建文档/整份替换”、目标文档、命中 H2 和保留的首次创建位置。
4. 存在任何 `ERROR` 时必须修改源文件并重新上传，不能确认无效任务。仅有 `WARNING` 时仍应判断被移除内容是否重要；原始 HTML 中的重要文字必须先改为 Markdown。
5. 预检任务默认从上传起保留 24 小时。到期前确认“索引”；逾期未确认的任务会变为 `EXPIRED`，原始临时文件会被清理，需要重新上传。
6. 确认时系统会重新检查整份替换目标、H2 占用、用户配额和全局容量。知识库在预检后发生变化时，确认会失败并要求重新预检。
7. 确认后等待索引任务进入 `READY`。此时产生的是候选版本，尚未自动替换普通用户正在阅读的活动版本。
8. 在版本列表点击“预览”检查当前候选文档。预览只展示该候选文档的 H1 管理标识、H2-H6 和正文，不渲染完整知识库；应重点检查标题公式、上下角标、表格、代码、图片和长内容滚动。
9. 候选版本确认无误后点击“发布”。发布时系统再次检查 H2 唯一性；成功后，新版本成为该逻辑文档的活动版本，并在原首次创建位置进入整库连续正文。
10. 发布后从普通用户入口抽查连续正文顺序、H1 隐藏、Typora 式大纲、思维导图定位、公式、表格、图片及若干代表性问答。

不得把“文件上传成功”“预检通过”“索引 READY”和“版本已发布”视为同一状态。只有候选版本完成预览并明确发布，且完成必要的阅读和问答抽查后，该版本才算可交付。
